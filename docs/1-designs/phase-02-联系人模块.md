## 1. 我要解决什么问题？

- **业务目标**：
    - 实现搜索用户功能
    - 实现获取好友列表功能
    - 实现获取好友详情功能
    - 实现获取未读好友申请数量功能
    - 实现修改好友申请状态功能
    - 实现添加、删除好友功能
    - 实现拉黑、取消拉黑好友功能

- **验收场景**：
    - Given 手机号或邮箱存在 When 搜索 Then 返回匹配的联系人列表 - 模糊搜索 右模糊
    - Given 已经是好友 When 删除 Then 软删除好友表两者的列数据
    - Given 用户已登录 When 查看未读好友数量 Then 返回申请状态未读的数量
    - Given 用户已登录 When 获取好友列表 Then 返回该用户的好友列表
    - Given 用户已登录 When 获取好友详情 Then 返回好友的用户信息
    - Given 好友状态正常 When 用户拉黑 Then 将好友状态改为拉黑
    - Given 好友状态拉黑 When 用户取消拉黑 Then 将好友状态改为正常
- **关键不变量**：
    1. 好友申请幂等不可以重复申请累计
    2. 好友申请状态需要并发保护, 需要标记已经修改了, 后续不可以修改状态
    3. 修改好友申请状态和好友的添加需要确保为事务, 要么全部成功, 要么全部回滚

## 3. 我的初版技术设计（重点由自己填写）

- **核心流程 / 状态变化**：
    1. 搜索用户: 搜索手机号或邮箱 -> 数据库右模糊查询 -> 返回匹配的用户
    2. 获取好友列表: 数据库查询好友表(好友表采用两人 userID 比较大小之后塞入同一列)经用户的 userID -> 筛选出来的好友 userID 查询其信息 -> 返回好友列表
    3. 获取好友详情: 根据好友 userID 查询用户表 -> 返回详细数据
    4. 获取未读好友申请状态: 数据库查询该用户申请表状态为 Unread
    5. 实现修改好友申请状态功能: 开启事务 -> 申请表状态修改 -> 判断好友表信息是否落库 -> 完成事务
    6. 添加、删除好友功能: 添加请求 -> 创建申请表数据; 删除请求 -> 修改好友表字段
    7. 拉黑、取消拉黑: 请求 -> 修改好友表对应状态字段
- **API 契约 (prefix /api/contact)**：
    - `GET    /:userID/user/search?keyword=   搜索用户`
    - `GET    /:userID/friend                 获取好友列表`
    - `POST   /:userID/friend/:receiveuserID  发送好友申请`
    - `GET    /:userID/apply                  申请列表`
    - `GET    /:userID/applyCount             获取未读申请数量`
    - `DELETE /:userID/friend/:receiveuserID  删除好友`
    - `POST   /:userID/block/:receiveuserID   取消拉黑`
    - `DELETE /:userID/block/:receiveuserID   拉黑`
    - `POST   /:userID/application/:status    修改申请状态`
    - `GET    /:userID/friend/:friendID       获取好友详情`

- **数据模型与访问模式**：
    1. 好友表 采用业界流行的 Hash 比较方案 两 userID 按大小放在同一列
    2. 申请表 状态字段固定如上 约束 所规定的 需要给 userID 设置索引加快搜索

- **事务 / 并发 / 幂等策略**：
    - 添加好友时 需要事务

- **权限 / 失败处理 / 重试策略**：
    - 以上操作必须都为当前用户已登录状态进行
    - 失败返回业务统一错误状态定义

## 4. 我自己的推理

- **为什么选这个方案？**：
    - 两 userID 存放统一列方案, 可以减少内存占用空间, 两者强关联不会有孤立数据, 天然保证两者状态一致性
- **考虑过的另一种方案及不采用的原因**：
    - userID 双方各自存储, 占用内存空间翻倍, 并且需要同时修改两者数据状态

## 5. 如何证明设计可行？

- **正常场景测试**：
    1. 搜索用户 -> 返回匹配的用户列表
    2. 获取好友列表 -> 返回该用户的好友列表
    3. 获取好友详情 -> 返回该好友用户的信息
    4. 获取未读好友申请状态 -> 返回该用户下的申请表状态为 Uread 的数据
    5. 修改好友申请状态 -> 判断状态 -> 根据状态决定是否更新好友表 -> 更新申请表 -> 返回成功
    6. 添加、删除好友 -> 正确更新数据库好友表状态字段 -> 返回成功
    7. 拉黑、取消拉黑好友 ->  正确更新数据库好友表对应状态字段 -> 返回成功
- **异常/边界场景测试**：
    1. 搜索用户不存在 -> 返回业务 NotFound
    2. 修改好友申请状态失败 -> 事务回滚 -> 数据库数据没更新保持不变
